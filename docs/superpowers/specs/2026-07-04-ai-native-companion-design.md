# 软眠眠 · AI Native 宿舍环境陪伴桌宠 — 设计文档

日期:2026-07-04
状态:已确认,待进入实现计划

## 1. 背景与目标

STM32 宿舍环境检测系统的**上位机**重构。下位机(STM32F1)通过传感器采集环境数据,经串口发给上位机;上位机是一个网站,读取串口数据、调用 AI 进行分析并输出。

本次重构的重点是 **AI native**:主线是**情感陪伴**,核心是**情绪价值**——把上位机做成一个像女朋友/姐姐/贴心小宠物一样的桌宠"软眠眠",在陪伴的同时用有温度的方式播报环境状态。

### 硬约束(不可动)

- **下位机程序保持不变。** 只开发上位机。
- **底层通讯原理逻辑不变。** 串口协议、波特率、帧格式一字不改。

### 下位机数据协议(现状,固定)

- USART1 @ 115200,每 ~2 秒发一行 JSON,以 `\n` 结尾。
- 正常帧:`{"temp":26,"humi":61,"mq135_adc":2886,"mq135_mv":2329,"motion":1,"sound_db":48}\n`
- DHT11 失败帧:`{"error":"DHT11_Failed","mq135_adc":...,"motion":...,"sound_db":...}\n`
- 六个字段:温度(°C)、湿度(%)、MQ135 空气质量(ADC,越小越差)、MQ135 电压(mV)、人体检测(motion,1 有人/0 无人)、噪声(sound_db)。

## 2. 核心理念:事实与灵魂分层

当前代码的架构是"规则决定一切,AI 只换个语气复述"——AI 是装饰层。真正的 AI native 要把这个关系反过来:

- **规则层 = 事实**:传感器数值的客观判断(范围校验、normal/warning/critical 分档、异常检测)全部由规则算出。这层保证软眠眠**永远不会编造数据**——它嘴里说出的每个数字和判断都来自规则给它的"事实卡片"。
- **AI 层 = 灵魂**:AI 拿着事实卡片 + 记忆 + 人设,决定**说什么、怎么说、什么时候主动说**。这是规则写不出来、只有 AI 能撑起来的部分,也是"AI native"的真正含义。
- **兜底**:AI 挂了/没网,软眠眠退回模板化的规则语气,依然"活着",只是话变得没那么灵。

一句话:**规则托底真实性,AI 负责人格和陪伴。**

## 3. 已确认的产品决策

| 维度 | 决策 |
|------|------|
| AI native 定位 | 情感陪伴主线(主动伴侣),情绪价值优先 |
| 人设 | 单一深度人设:软眠眠,黏人温柔的小女友型桌宠 |
| 记忆 | 持久化长期记忆(重启不忘) |
| 主动性 | 变化触发 + 定时触发 + 事件触发 |
| 界面形态 | 桌宠为绝对主角,数据收进抽屉 |
| AI 供应商 | DeepSeek(纯文本)为主;为未来语音/多模态留可插拔扩展口,本次不实现 |
| 兜底 | 保留并强化现有三层兜底,没网也能"活着" |
| 开发范围 | 只重构 AI/角色/前端层;串口/解析/协议不动,挡路才碰底层 |

### 关键选型(推荐值,已采纳)

- **记忆存储**:SQLite(单文件、无需装服务、支持结构化查询)。
- **主动消息通道**:SSE(Server-Sent Events),后端有话说时主动推送前端。
- **实施节奏**:分三期递进,每期都能独立运行演示。

## 4. 目标后端架构

拆分当前 1100 行的巨型 `app.py`。**串口/解析/质量判断三块逻辑原样搬迁,行为不变**;带 ★ 的是新增的 AI native 核心。

```
backend/
├── config.py         # 集中 os.getenv 配置
├── serial_io.py      # 串口读取 + 重连(搬现有 serial_reader/mock_reader)
├── parser.py         # 帧解析(搬现有 parse_line,协议不变)
├── quality.py        # 规则质量判断(搬现有 build_quality,即"事实卡片")
├── state.py          # 共享状态 + 历史(搬现有)
├── events.py         # ★ 事件检测引擎
├── memory.py         # ★ 持久化长期记忆(SQLite)
├── persona.py        # ★ 软眠眠人设 + prompt 构建
├── ai_provider.py    # ★ 可插拔 AI 能力接口
├── brain.py          # ★ 大脑,整合以上 → 决定发言
└── app.py            # 只剩 Flask 路由,变薄
```

## 5. AI 大脑与人设

- **人设**:单一深度人设——软眠眠,黏人温柔的小女友型桌宠。system prompt 固定性格、称呼习惯、语气边界(温柔但不腻、会撒娇、会关心)。
- **语气硬约束(写进 prompt)**:回复必须始终**温柔**——语气柔和、体贴、有耐心;用亲近柔软的措辞和称呼;即使在提醒异常或用户情绪不好时,也保持轻声安抚的口吻,不生硬、不说教、不命令、不冷淡。这是不可违反的语气底线。
- **防编造硬约束(写进 prompt)**:只能基于事实卡片说话;不许推断时间/季节/门窗/用户在干嘛;不许编造传感器没有的数字。
- **grounding**:每次调 AI,`brain.py` 打包塞入——实时事实卡片(规则算出的 6 项判断)+ 相关长期记忆 + 刚发生的事件 + 最近对话历史。AI 只在这张"真实底稿"上做情感化表达。

## 6. 记忆系统(SQLite)

三类记忆:

- **用户档案**:从对话抽取的长期事实("我叫小北"、"我怕冷"、"我一般一点睡")。由 AI 识别并写入,重启不忘。
- **对话摘要**:旧对话定期压缩成摘要,避免上下文无限膨胀,又保留"记得你说过的话"。
- **环境记忆**:每段时间的环境概况("今天下午屋里一直偏闷"),支持跨时间观察。

## 7. 主动性引擎

后台线程持续观察数据,三种触发:

- **变化触发**:质量等级跳变(如 normal→warning)、数值突变。
- **定时触发**:平稳时每隔一段(可配,约 15–20 分钟)来一句陪伴,带去重和节流。
- **事件触发**(从数据组合检测出的"有灵性"时刻):
  - motion 0→1(久无人后)→"你回来啦~"
  - 深夜(用系统时间,非猜测)持续有人 →"这么晚还不睡呀"
  - 湿度连续上升 N 帧 →"屋里越来越潮了,我有点担心你"
  - 空气 ADC 持续走低 →"感觉有点闷,要不要开窗透透气"

前端通过 SSE 即时收到主动消息。

## 8. 前端 / 桌宠

- 界面形态:桌宠为绝对主角,满屏是软眠眠 + 对话气泡 + 输入框,数据全部收进抽屉。
- 桌宠形象:在现有 CSS 呼吸小团子基础上进化——眨眼、随情绪切表情(舒服/担心/警觉/困)、主动说话时有动作、被点有反应。
- 具体视觉形象在进入第三期实现时,用可视化方式画出来一起定。

## 9. 兜底与错误处理

保留并强化三层兜底,各层独立,一层挂不拖垮其他层:

1. AI 失败 → 规则语气。
2. 后端不可达 → 前端本地兜底。
3. 设备离线 → 桌宠显示"困了/待机",页面照常。
4. 新增:记忆写入失败不影响对话;事件引擎出错不影响实时数据展示。

## 10. 分步骤开发计划

### 第一期 · 骨架重构(行为完全不变,只搬家)

目标:拆分 `app.py`,验证拆完后功能与现在一模一样。不加新功能。

- **Step 1.1** 建 `backend/`,配置集中到 `config.py`,共享状态搬到 `state.py`。验收:导入不报错。
- **Step 1.2** 抽离 `parser.py`(`parse_line` 等),协议字段一字不改。验收:单元测试喂真实帧(含 error 帧),结果与现在一致。
- **Step 1.3** 抽离 `quality.py`(`build_quality`,即事实卡片)。验收:同数据输出 quality 逐字段相等。
- **Step 1.4** 抽离 `serial_io.py`(`serial_reader/mock_reader/process_frame`);`app.py` 只留路由。验收:`MOCK_SERIAL=true` 启动,前端显示与现在一样。

里程碑:行为等价、结构清爽的后端。

### 第二期 · AI native 核心(灵魂注入)

目标:让软眠眠有性格、有记忆、会主动。前端暂用现有页面验证。

- **Step 2.1** `ai_provider.py`:统一接口 `chat(messages) -> str`,实现 DeepSeek,留 provider 抽象。验收:独立调通一次请求,失败抛明确异常。
- **Step 2.2** `persona.py`:固化软眠眠人设 system prompt + 防编造硬约束。验收:给定事实卡片,生成的 prompt 含人设 + 约束 + 数据。
- **Step 2.3** `memory.py`(SQLite):三张表(用户档案/对话摘要/环境记忆)+ 写入/检索接口。验收:写入后重启能读回。
- **Step 2.4** `brain.py`:整合事实卡片 + 记忆 + 对话 → 调 AI → 软眠眠的话;AI 失败回退规则;从对话抽取长期记忆写回。验收:对话接口接上 brain,回答带人设、能引用记忆、断网优雅退回。
- **Step 2.5** `events.py`:三类触发(变化/定时/事件),带节流去重。验收:mock 构造 motion 0→1、湿度连升,能观测到对应主动发言。

里程碑:真正 AI native 的陪伴大脑,旧前端即可聊天 + 收主动消息。

### 第三期 · 桌宠前端(把灵魂显出来)

目标:重做界面,桌宠为绝对主角。

- **Step 3.1** SSE 主动推送:后端 `/api/stream`,主动发言推给前端。验收:后端主动发言,前端无刷新冒气泡。
- **Step 3.2** 桌宠形象与表情:眨眼、随情绪切表情、说话动作、点击反应;开始时用可视化工具定形象。验收:切换环境状态,桌宠表情随之变化。
- **Step 3.3** 对话与记忆展示:沉浸式气泡流 + 输入框,数据收进抽屉;可选"她记得的事"面板。验收:走通"聊天→记住→重启仍记得→主动关心"闭环。
- **Step 3.4** 收尾:更新 README 到真实 6 字段 + 新架构;清理临时文件。
